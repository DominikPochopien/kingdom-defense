# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Kingdom Defense is a tower defense game in Godot 4 (GDScript, `gl_compatibility` renderer). It has no build step, linter or tests. To run it, open `project.godot` in the Godot editor and press F5. The main scene is `main.tscn`. Godot is not on PATH. If the `godot-ai` MCP server is connected, it can drive the editor.

All in-game text, comments and `README.txt` are in Polish. Keep new UI strings and comments in Polish to match. **Respond to the user in Polish.**

## Architecture

The whole game lives in one script, `main.gd` (~2000 lines). It is attached to a single `Node2D` in `main.tscn`. The game has no other scenes, nodes, sprites or audio files:

- **Rendering:** everything is drawn by hand in `_draw()` with `draw_*` calls. `_process` calls `queue_redraw()` every frame. The logical resolution is fixed at 1280×720 (`W`/`H`), and the window scales via `content_scale_mode`. The HUD bar takes `TOP` = 44 px.
- **Audio:** sound effects are synthesized at startup into `AudioStreamWAV`s (`make_tone`, `_setup_audio`) and played with `sfx(name)`.
- **UI/input:** buttons are hard-coded `Rect2`s (`R_*` vars). The context menu around a build spot is generated by `menu_buttons()` as dicts made with `mbtn()`. `handle_click` hit-tests those rects according to `state`.
- **State machine:** the string `state` takes the values `"menu" | "levels" | "play" | "win" | "lose"`. Both `_draw()` and `handle_click()` branch on it.

### Data-driven balance and maps
The dictionaries at the top of `main.gd` drive the content:
- `TOWERS`: base stats per tower type. Towers have levels 1–3. At level 3, the player picks one of two `BRANCHES` (level 4). Stat getters such as `t_dmg`, `t_range`, `t_rate`, `t_splash` and `soldier_hp` apply the level and branch modifiers. Change tower behaviour there, not in the base dicts.
- `ENEMIES`: `armor` reduces physical damage and `mr` reduces magic damage, both on a 0..1 scale. Optional `"ability"` (e.g. `"heal"` for shamans).
- `LEVELS`: an array of maps. A level uses either `"path"` (one route) or `"routes"` (several routes). Optional keys enable special mechanics:
  - `river` (polygon)
  - `bridges` / `fixed_bridges`
  - `bridge_period`
  - `shamans`
  - `random_routes_from` (wave number from which enemies pick a random route)
  - `special_tower` (spot index that gets a free, unsellable `knight_tower`)

`setup_level()` turns the waypoints into `routes` (`{pts, cum, len}`), where `cum` holds cumulative distances. Enemies move by distance along their route (`e.dist`, `e.route`), and `path_pos(d, ri)` converts that distance to a screen position.

### Lightweight data classes
`Enemy`, `Soldier`, `Tower`, `Spot` and `Proj` are inner classes used as plain records. Entities stay in arrays (`enemies`, `soldiers`, `projectiles`, `strikes`, `fx`, `floats`) and are flagged (`dead`, `gone`, `done`) during `update_game`. They are removed with `filter()` at the end of each tick. Towers belong to `spots[i].tower`.

### Time
`update_game(delta * game_speed)` runs only while playing and not paused. Bridge raise/lower animation (`update_bridges`) runs on real time, separately from the bridge-switch logic (`update_bridge_logic`, game time). A bridge cannot close while enemies are in its zone (from the fork, `zone_from`, to `zone_to`).

### Save system
Saves go to `user://save.cfg` through `ConfigFile`:
- `[progress]` holds `unlocked` and `completed[]`.
- `[runs] level_N` holds a mid-level checkpoint: gold, lives, wave, cooldowns, towers by spot index, and bridge state.

`save_run()` writes only when `is_quiet()` (between waves). It is called automatically when a wave is cleared and after building or upgrading. `continue_run`/`restore_tower` rebuild the run from the checkpoint. Win or loss deletes the checkpoint. If you add per-run state, add it to both `save_run` and `continue_run`.

### Level select
The level select screen is a fixed 3×2 grid (`LEVEL_SLOTS` = 6) with paging. Slots without a level show "Wkrótce" ("Coming soon").
